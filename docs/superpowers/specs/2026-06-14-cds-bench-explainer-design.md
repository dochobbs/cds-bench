# cds-bench Interactive Explainer + Readable Queries — Design Spec

**Date:** 2026-06-14
**Status:** Approved (brainstorming complete)
**Repo:** `/Users/dochobbs/Downloads/Consult/cds-bench`
**Topic:** A self-contained interactive HTML explainer at the repo root + a Markdown render of the public queries, both generated from the 29 public cases, leak-safe by construction.

---

## 1. Goal

Make the benchmark legible to a human: render the **29 public cases** as human-readable, formatted queries (not raw JSON), wrapped in a single-file interactive explainer that also documents the methodology, guardrails, worked examples, and evolution. Plus a git-diffable Markdown render of the same public cases.

**Hard constraint:** every human-facing artifact renders the **29 public cases only**. The 116 held-out cases are never in scope, and no private path may appear.

## 2. Decisions locked (from brainstorming)

| Decision | Choice |
|---|---|
| Doc scope | **Full explainer** — methodology + interactive case browser + worked examples + evolution/citations |
| Readable queries | **HTML + Markdown** (`docs/PUBLIC_CASES.md`) |
| Production & placement | **Generated by a builder**, committed `index.html` at repo root + `docs/PUBLIC_CASES.md`, and also emitted into `dist/public/` by `build_public` |
| Design language | Reuse the existing `cds_eval_explainer.html` system (paper/teal/coral, serif, single file, zero external deps) |

## 3. Architecture — shared pure renderers, two callers

New module `scripts/release/build_explainer.py`:

| Unit | Responsibility |
|---|---|
| `load_public(bench_dir=BENCH_DIR) -> dict[str, list[dict]]` | the 29 `split=="public"` cases grouped by lane name (mirrors `submit.load_hidden`) |
| `render_html(public, *, rubrics) -> str` | the self-contained `index.html` string |
| `render_markdown(public) -> str` | the `PUBLIC_CASES.md` string |
| `_assert_no_private_path(text, label)` | raises if `/users/` or `/tmp/gemvenv` (case-insensitive) appears |
| `main()` | writes committed `index.html` (repo root) + `docs/PUBLIC_CASES.md` |

Callers:
- `python -m scripts.release.build_explainer` → committed source copies (root `index.html`, `docs/PUBLIC_CASES.md`).
- `build_public` imports `render_html`/`render_markdown` and writes `index.html` + `PUBLIC_CASES.md` into `dist/public/` (published copies). **No file copying — both paths call the same renderers.**

Rubrics passed to `render_html` are read from `release_clean/rubrics/<lane>.txt` (already vendor-blinded and gated by `build_public`).

## 4. Safety model (gate scoping)

- The renderers receive only `load_public()` output → hidden cases structurally absent.
- Embedded **methodology/rubric** text originates from `release_clean/` → already vendor-clean.
- The full vendor-word gate (`_assert_clean`) is **deliberately NOT** run over embedded *clinical case text*: `ground-glass` and `LISA` (Less Invasive Surfactant Administration) are legitimate clinical terms that collide with the `glass`/`lisa` vendor tokens. Embedding public case text is no more exposure than the `public/*.json` already published (intentionally un-vendor-gated for the same homograph reason).
- Defense-in-depth: `_assert_no_private_path` runs over the **final** rendered HTML and MD — private paths never appear in legitimate clinical/methodology text, so zero false positives, and it catches an accidental absolute-path leak.

## 5. HTML sections (single file)

1. **Hero** — what cds-bench is; the 29-public / 116-held-out framing; the do-not-train notice + canary shown plainly.
2. **Methodology** — lane table (lane × n × what it tests); fixed-seed proportional split; guardrails (canary / SHA-256+Merkle manifest / eval-as-a-service); judge protocol (median-of-3 @ temp 0.3, anti-anchoring, date-aware, verifiable-only citations).
3. **Case browser** — lane-filterable cards; each shows the formatted query + lane-specific gold:
   - golden: query + rubric dimensions
   - freshness: query + `old_answer → new_answer (source)`
   - hallucination: query + `trap / expected`
   - halluhard: query + `rarity · grounding_axis · fail_modes · ground_truth_source`
   - calc: query + `calculator / expected_behavior`
4. **Worked examples** — the 5 showcase cases (`G52, F19, H11, HH08, C01`) with full query+rubric+gold; renders transcript+score too if a curated overlay exists (graceful absence today).
5. **Evolution + references** — postmark timeline + citations, embedded as concise structured Python data (no markdown-parser dependency); links to `docs/EVOLUTION.md` for full text.
6. **Footer** — license summary + links to repo docs.

Interactivity: inline vanilla JS for lane filtering + text search over the embedded case JSON. No external scripts/fonts/CDNs.

## 6. `docs/PUBLIC_CASES.md`

The 29 cases grouped by lane, each a readable block (query + gold fields). Header states "public sample (29 of 145) — do not train." Same renderer family as the HTML.

## 7. Testing (`tests/release/test_explainer.py`, pure-string, no browser)

- `render_html` output contains exactly the 29 public ids and **no hidden id** (assert a sample of known hidden ids absent).
- HTML + MD contain no `/users/` or `/tmp/gemvenv`.
- Each of the 5 lane sections present in the HTML; each lane's gold fields rendered.
- `_assert_no_private_path` raises on planted `/Users/...`.
- `render_markdown` lists 29 cases across 5 lanes.
- `load_public` returns 29 with `{lane,id,case}` shape.

## 9. Non-goals

- No external assets (fonts/CDNs/JS libs) — single self-contained file.
- No markdown-parsing dependency — evolution content embedded as structured data.
- No rendering of hidden cases, ever.
- Not a scoring tool — purely presentational over already-built data.
